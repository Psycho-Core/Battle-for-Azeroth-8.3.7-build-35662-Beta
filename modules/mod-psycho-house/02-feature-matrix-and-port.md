# 02 - Feature matrix and port plan

Every retail housing feature, what 8.3.7 build 35662 can actually do with it, how
mod-psycho-house implements it, and what it costs. This is the document I work from; doc 04
is what I promise to players and doc 05 is the schedule.

Effort scale: **S** <= 1 evening, **M** 2-4 evenings, **L** 1-2 weeks, **XL** 3+ weeks.
Priority: **P0** foundation (nothing else works), **P1** launch, **P2** post-launch,
**P3** maybe never.

## 1. The five hard substitutions

Everything else in this document is detail. These are the places where retail's
implementation cannot be copied even conceptually, so they define the port.

| # | Retail has | 8.3.7 does not | mod-psycho-house does instead |
| --- | --- | --- | --- |
| 1 | Native housing UI + Housing Dashboard (H) | Any housing UI, and no way to add client-side UI without an addon | **Full addon** (`PsychoHouse`) over the addon channel, plus gossip and a `.house` command fallback |
| 2 | Modular room system with snapping floorplans | Any room geometry or room DB2 | **Shell rooms**: authored WMO/GO room shells placed by the server; the player picks shells and the server positions them. No arbitrary tiling. (doc 06 sec.1) |
| 3 | Housing decor DB2 + decor items | Both | **`housing_decor` world table** mapping a synthetic decor id to an existing 8.3.7 **game object template** - my decor is a GO id with metadata |
| 4 | Warband | Warband | **Account** is the ownership unit, exactly as the prototype already does |
| 5 | Blueprint codes generated by the client | Any client-side serialiser | **Server-generated codes**: the addon asks, the server packs the house into a compact text code (doc 06 sec.3) |

The consequence of substitution 1 is that *every* interaction has to exist twice: once in
the addon protocol (pretty) and once as chat/gossip (works for everyone, including people
who do not want an addon). The prototype already does this; the port keeps it and adds the
gossip paths that are missing.

## 2. Feature matrix

Every row below has an implementation in `modules/mod-psycho-house/src`, and the column says
where. A row that names a file and a function is a row that runs; a row that says **blocked**
is one where the client or the core genuinely cannot do it, and the reason is in the cell.
The effort and priority columns are the plan I wrote before the code existed; they are left as
written so the estimate can be compared with what it took.

| Retail feature | Why not | What players get instead |

## 5. The three things that will actually be hard

1. **Room shells.** Not the code - placing GOs at fixed offsets is easy - but the **art**:
   authoring enough shells that a house does not look like six identical boxes. Doc 06 sec.1.
2. **Dyes.** GO material colour is not runtime-mutable. Everything else in this document is
   data; this is the one place where the honest answer is "only works for pieces that have
   authored colour variants". Doc 06 sec.2.
3. **Endeavors that feel alive.** The engine is bookkeeping; the *content* is 30+ task
   definitions that map to things players already do in 8.3.7 and 12+ themed vendor sets.
   Budget most of the P3 content time here. Doc 04 sec.4.

Everything else - ownership, travel, budgets, catalogue, placement, permissions, vendors,
persistence, the addon protocol - is already implemented in the prototype and is a
rename-and-extend job.

## 6. The small draft that ships first

Section 5 is the honest cost list, so it needs one honest counterweight: there is a smaller
system hiding inside this one, and it is now written - `drafts/mod-psychohouse/`, described in
doc 13.

It is one house per character on GM Island: buy a key, walk in, buy services from a Steward,
walk out. No decor, no budgets, no placement, no Endeavors. Two conclusions belong here:

- **it is not a substitute.** Every mechanism in sections 2.4, 2.6 and 2.7 is absent from it;
- **it is an addendum.** The facility layer is the one thing this plan was missing (doc 05
  sec.4.6), it is independent of decor, and it can be built first and survive any later cut.

If placement ever proves too expensive to finish, the neighbourhood module minus 2.4, 2.6 and
2.7 still leaves something worth playing, and that something is already written rather than
merely planned.
